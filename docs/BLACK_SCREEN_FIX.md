# 自定义时钟刷新闪黑修复

日期：2026-10-22（项目记录日期，America/Chicago）。

**最终方案保留自定义 TAIPEI 界面、台湾时间和秒数，使用实时位图上传加重绘触发。** 用户实物反馈：“正常了，秒数更新且没有滚动或闪黑”。默认后台时钟已经采用此流程。

> 后续变更：默认时钟随后改为北京时间（UTC+8）和 `BEIJING` 界面，更新流程不变，见 [北京时钟](BEIJING_CLOCK.md)。下文的台湾时区和 `.runtime/taipei-clock.log` 是当时的记录；该日志现名为 `.runtime/beijing-clock.log`。

## 根因与修复

旧时钟每次更新都走 `0x61` 的完整动画上传流程。上传中断会造成黑屏，即使每包都收到确认，每次重新上传也会打断显示。放慢到 3 秒只降低闪黑频率，用户仍报告“每三秒黑一次”。

正确路径利用原厂音乐信息的位图渲染器：

1. `0x67 / sub=0`：设为仅显示信息位图，宽 208、高 64，113 个数据包。
2. `0x67 / sub=1`：上传一帧原始 4bpp 数据，共 6656 字节，包序号递减。
3. `0x67 / sub=2`：发送全零载荷，触发屏幕重绘。

第三步是关键。只做前两步，25 次上传都能收到 ACK，但用户看到的仍是原时钟，秒数不动。加入全零重绘触发后，用户确认原来的自定义时钟开始固定更新，没有滚动或闪黑。

这条通道只发送自定义位图及全零触发数据，无需播放、采集或读取音乐。它也不使用原厂时钟的视觉样式。

## 代码与验证

- `tools/oled.py::RogOled.live_upload`：模式、位图、重绘三个步骤；模式或数据包失败时不触发重绘。
- `tools/show.py::push_live`：渲染器产生的画面直接转换为单帧位图。默认 clock 页面使用此函数，目标每秒更新。
- `tests/test_live_bitmap.py`：验证 115 份报告的结构、113 个数据包、像素重组一致性、全零触发包及失败处理。
- 现有台湾时区、像素顺序、旧动画与错误处理检查一并通过，共 14 项。

原型连续更新 25 次后，用户确认实物正常。接入默认后台后，日志记录了超过 4 分钟、244 次成功更新；之后设备短暂未响应模式命令，后台进入等待状态，随后自动恢复，成功更新计数继续增加至 349。标准错误输出为空。记录位于本机 `evidence/black-screen/music-redraw.log`、`checks-final.txt`、`final-runtime.log` 与 `.runtime/taipei-clock.log`。这不能证明设备在休眠时仍会亮屏。

重绘命令对应原厂 `SetSpectrumData`：原厂仅写入，不等待 ACK。因此通信日志只证明位图上传与触发已发送，实物无滚动、无闪黑的证据来自用户观察。

## 查证来源

本地原厂反编译代码 `GearLink_KBApi.decompiled.cs` 中的 `MusicMode_GRAY_Type_1.SetMusicMode`、`SetMusicInfo`、`SetSpectrumData` 提供 `0x67` 流程。`GearLink_KBAgent.MergePixel` 提供 4bpp 像素顺序。

同时读取了华硕官方发布的夜魔 X 网页端驱动：[7205 manifest](https://gearlink.asus.com/view/7205/manifest.json)。本次版本为 `1.00.36`，bundle ID 为 `7205-1788853886-573994`。下载文件保留在本机 `evidence/black-screen/gearlink-js/`，没有执行下载的 JavaScript，也不把第三方完整代码提交到仓库。

## 已排除的方案

| 方案 | 实物或设备结果 |
|---|---|
| 动画上传后立即重传 | 中途返回拒绝，产生黑屏 |
| 动画间隔改为约 3 秒 | 上传更稳定，但用户确认每次更新仍闪黑 |
| 跳过 mode、复用动画会话 | 第 0 个数据包未被确认 |
| 横幅 `0x62` | 唤醒后可上传，但几个已试样式会滚动，用户不接受 |
| 原厂时钟 `0x63` | 可以显示台湾时间，但用户要求保留自定义界面，未作为最终方案 |
| 音乐位图只上传、不触发重绘 | 数据有 ACK，但实物保留旧画面 |
| 独立页面切换 `0x6A` | 本机此次尝试返回拒绝，最终方案不依赖它 |

## 保留的限制

键盘自身的休眠策略没有修改；正常休眠仍需按键唤醒。当前修复针对实时刷新造成的闪黑。实际刷新间隔受 USB 和无线链路耗时影响。

旧动画入口保留 2 秒冷却与整帧重试保护，避免再次从中间包续传不完整会话。实时位图时钟不走旧动画路径，也不需要该冷却期。
